Agents are great at the task. They lose the story.

Coding agents plan, write, and test well inside one session. They do not keep a record of why the project moved the way it did. That record usually lives in one chat, and chats do not last.

  • Compaction

    A long session fills the context window. The harness summarizes it, and the reasons behind early decisions drop out.

  • New sessions

    Tomorrow's session starts blank. You spend the first ten minutes explaining what you already explained yesterday.

  • Switching tools

    You move from Claude Code to Codex or Cursor. Each tool keeps its own history, and none of them read the others'.

Three tools. Markdown underneath.

Goldfish is an MCP server with three tools. The agent calls them; the files land in a .memories/ folder in your project; git carries them everywhere the code goes.

checkpoint

Save what happened and why

At each milestone the agent writes a short structured note: what changed, why, how, and what it unblocks. Goldfish adds the time, branch, commit, and changed files for you. 

---
id: checkpoint_a1b2c3d4
timestamp: 2026-09-22T14:30:22.000Z
tags: [bug-fix, auth]
git:
  branch: fix/jwt-timeout
  commit: 3f9c21e
  files: [src/auth/jwt.ts, tests/auth.test.ts]
symbols: [RefreshTokenStore, validateToken]
---

## Fixed JWT timeout with refresh-token rotation
...

brief

Keep the direction steady

A brief is a short document with the goal, the constraints, and what success looks like. It sits at the top of every recall, so each session starts pointed the same way. 

---
id: auth-system-redesign
title: Auth System Redesign
status: active
---

## Goal
Redesign auth around durable refresh-token sessions.

## Constraints
- Keep one-release compatibility for old clients
- Do not break admin SSO

recall

Bring it back when it matters

Recall returns the active brief and recent checkpoints. It can also search by keyword, filter by date, tag, or type, and answer "who touched this file, and why?" 

# the last 5 checkpoints and the active brief
recall({ workspace: "/path/to/project" })

# keyword search, ranked by relevance
recall({ workspace, search: "auth timeout" })

# why did this file change?
recall({ workspace, file: "jwt.ts" })

# every project, for a standup
recall({ workspace: "all", days: 1 })

What you get

Memory that travels with the code
Checkpoints are committed files. Clone the repo on another machine and the history comes with it.
Reviewable in pull requests
A checkpoint shows up in the diff next to the code it explains. Reviewers see the reasoning, not only the result.
One memory for every tool
Claude Code, Codex, Cursor, and other MCP clients read and write the same .memories/ folder. Switch tools without losing the thread.
Readable without Goldfish
Every entry is markdown with a small header. Open it in any editor, grep it, or browse it as a table in Obsidian.
Answers "why is it like this?"
Filter recall by file or function name to find the decision behind a line of code, like git blame for intent.
Standups and handoffs for free
/standup summarizes work across all your projects. /handoff writes a resume note for the next agent or the next you.
Fast and small
A save takes about 10 ms. A week of recall takes about 30 ms. No database, no background service, three runtime dependencies.
Quiet by design
One static note loads when a session starts. No hooks fire during your work, and nothing phones home.

Best practices

Goldfish stores what the agent writes, and nothing smarter. The value of your memory depends on the quality of each entry. These habits make the difference.

Write what, why, how, and impact

A future session reads only these words. Name the files and functions you touched, the reason for the change, the options you rejected, and what comes next. Add symbols so file and function searches find it later.

Checkpoint at milestones, not every step

One checkpoint per meaningful unit of progress. Good moments:

  • A feature, fix, or refactor step is done
  • You made a key decision or found something surprising
  • You are about to stop for the day
  • The context window is about to compact

Checkpoint before you commit

Save the checkpoint first, then commit. The checkpoint file goes into the same commit as the code it describes, so the two never drift apart.

Always commit .memories/

The folder is a project record, like docs or tests. Never add it to .gitignore. Each checkpoint is its own file, so teammates and parallel agents do not get merge conflicts.

Use briefs for direction, not task lists

Your harness already plans the steps of a session. A brief holds what outlasts a session: the goal, the constraints, and the finish line. Link to detailed plans instead of pasting them in.

Keep the brief honest

Update the brief when goals or constraints change. Complete it when the work lands. Archive it when a new direction replaces it. Goldfish warns you when an active brief goes stale.

Recall when the past matters

Recall when you resume earlier work, after a compaction, or when an old decision affects the task. A quick question in a new session does not need it.

Treat recalled facts as history

Keep the decisions. Check the details that change over time, such as file paths, versions, and test counts, against the current code before you rely on them.

Six skills for the common jobs

The plugins add slash commands that wrap the three tools in good habits. Clients that read .agents/skills/ get them too.

CommandWhat it does
/checkpointSave a well-structured checkpoint with tags
/recallRestore context from recent checkpoints and the active brief
/briefCreate or update the direction for multi-session work
/brief-statusCheck progress against the active brief, with evidence
/handoffWrite a resume summary for a returning or different agent
/standupReport recent work across all your projects

Install

Goldfish runs on Bun 1.0 or later. Install Bun first.

Install the plugin from inside Claude Code. You get the tools, the six skills, and a start-of-session note that reminds the agent how to use them.

/plugin marketplace add anortham/goldfish
/plugin install goldfish@goldfish

Start a new session after the install. Run /hooks to see the Goldfish session-start entry.

One plugin install covers the Codex CLI and the Codex desktop app.

codex plugin marketplace add anortham/goldfish
codex plugin add goldfish@goldfish

Codex does not run plugin hooks until you trust them. Run codex, open /hooks, trust the Goldfish SessionStart hook, then start a new thread.

To update later, refresh the marketplace first, then remove and add the plugin:

codex plugin marketplace upgrade
codex plugin remove goldfish@goldfish
codex plugin add goldfish@goldfish

Cursor loads Goldfish as a local plugin. Clone the repo, install dependencies, and link it into Cursor's plugin folder.

git clone https://github.com/anortham/goldfish.git
cd goldfish && bun install
mkdir -p ~/.cursor/plugins/local
ln -s "$PWD" ~/.cursor/plugins/local/goldfish

Reload the window, then check that Goldfish shows under Customize. On Windows, use a junction or a copy instead of the symlink. The README has the PowerShell commands and the per-project config.

Clone the repo and run bun install. Then add the server to opencode.json. OpenCode finds the skills in .agents/skills/ on its own.

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "goldfish": {
      "type": "local",
      "command": ["bun", "run", "/absolute/path/to/goldfish/src/server.ts"],
      "enabled": true
    }
  }
}

Clone the repo and run bun install. Then register the server with the Antigravity CLI:

agy mcp add goldfish bun run /absolute/path/to/goldfish/src/server.ts

To use the six skills in every project, add the skills folder to ~/.gemini/config/skills.json:

{ "entries": [ { "path": "/absolute/path/to/goldfish/skills" } ] }

Clone the repo and run bun install. Then add the server to .vscode/mcp.json in your project:

{
  "servers": {
    "Goldfish": {
      "type": "stdio",
      "command": "bun",
      "args": ["run", "/absolute/path/to/goldfish/src/server.ts"],
      "env": { "GOLDFISH_WORKSPACE": "${workspaceFolder}" }
    }
  }
}

For good Copilot habits, copy the ready-made instructions file into .github/instructions/.

Goldfish is a standard stdio MCP server. Any client that can start a local server can use it:

bun run /absolute/path/to/goldfish/src/server.ts

If the server is registered for your user rather than one project, the agent must pass the project's absolute path as workspace on each call.

Harnesses that read only an instruction file, such as Zed, Windsurf, Cline, or Kiro, can use the Goldfish usage rules. The tools still need the MCP server.
