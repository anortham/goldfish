## Aligned the six skills with the Anthropic skill best-practices guide

The user asked for a comparison against https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices and then decided: **the official Anthropic docs win over the razorback writing-skills guidance**.

- **Descriptions:** each skill now opens with a third-person "what it does" sentence, then "Use when …". Every old trigger phrase is kept. Razorback says descriptions list triggers only; that rule was overruled.
- **MCP tool names:** the guide asks for fully named MCP tools. The prefix changes by host, so each skill now has one line that names the goldfish MCP server, gives `mcp__plugin_goldfish_goldfish__recall` as an example, and says to search for the tools before concluding they are missing.
- **Stale facts in `checkpoint`:** "fuzzy search" became BM25, the "daily markdown file" example became "a checkpoint file", and the concept tag range went from 2-5 to 3-6 to match the examples.
- **`handoff`:** removed the "Why This Skill Exists" rationale, a filler line, and the duplicate "Time Scoping" section.
- **Names kept:** `recall`, `brief`, and the other names stay. The guide accepts them, and a rename breaks the slash commands. If a clash shows up in unprefixed `.agents/skills`, use a `goldfish-` prefix instead of "-ing" names.

**Tests:** `tests/agent-assets.test.ts` now checks the published name and description limits, the "what, then Use when" description shape (parsed with `yaml`), the tool-source line, and that no skill mentions fuzzy search or a daily file.
