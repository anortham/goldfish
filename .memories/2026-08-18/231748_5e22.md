## Fixed the Windows MCP JSON checkpoint failure with description_file

The TODO user report: on Windows, three ~4KB inline checkpoint descriptions failed with `InputValidationError` before Goldfish ran. The host rejects tool-call JSON when the model emits unescaped `\` (Windows paths), unescaped control characters, or truncated output.

- **Verified first:** the parse errors reproduce locally; Goldfish accepts the same 4KB payload over a real MCP client when the JSON is valid; the error string exists in neither Goldfish nor the MCP SDK. Claude Code issues #5504 and #14442 match the report.
- **Fix:** new optional `description_file` checkpoint parameter. Exactly one of `description` / `description_file` is required. Relative paths resolve against the workspace with `\` separators normalized; missing and empty files give clear errors with the resolved path; the file is never deleted.
- **Guidance:** checkpoint skill, tool description, and hook quick reference now say: keep inline bodies under ~2KB, use `/` separators, draft long bodies under `.memories/`, delete the draft after the save. `required: ['description']` dropped from the schema; the handler validates instead.
- **Design doc:** docs/plans/2026-08-18-checkpoint-description-file-design.md
- **Impact:** large checkpoint writeups can no longer be lost to host-side JSON escaping. Version bump and release are deferred; the CHANGELOG entry sits under Unreleased.
