## WHAT
Completed and lead-reviewed the runtime implementation for fail-closed workspace identity. The core resolver accepts only verified explicit absolute paths, fixed `GOLDFISH_WORKSPACE`, or supported legacy Roots; the MCP adapter rejects unbound calls before handlers; direct handlers and storage entry points bind before filesystem access; recall-only `workspace: "all"` remains explicit; and cross-workspace caches are covered by isolation tests.

## WHY
Codex and Cursor user-level MCP registrations provide no trustworthy per-project cwd, and MCP 2026-07-28 is sessionless. Cwd, registry recovery, and parent walking could silently read or write the wrong `.memories/`, including plugin caches. The approved design removes those authorization paths rather than adding activation state.

## HOW
Used strict TDD and three Luna packets. Task 1 introduced the async verified resolver and fixed a reviewed worktree-root edge case. Task 2 removed recovery selection/notices, retained suggestion-only registry formatting, added modern spawned-stdio refusal and legacy spawned-stdio Roots coverage, and fixed empty explicit arguments so they cannot fall through. Task 3 awaited binding throughout handlers/storage, preserved worktree and Git behavior, added two-workspace day/brief/search isolation, and fixed recall so handler binding occurs before injected dependencies. Focused results: workspace 69 pass/1 skipped; server/recovery/protocol 64 pass; handlers/checkpoints/briefs/recall 405 pass.

## IMPACT
User-level calls without an explicit absolute project root now fail safely instead of selecting cwd or registry state. Project-level fixed environment binding and legacy Roots still work. Runtime code is ready for the remaining Task 4 contract, skill, hook, and documentation updates before full integration and branch verification.
