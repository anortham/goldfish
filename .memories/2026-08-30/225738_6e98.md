## Codex plugin recall bound to the plugin cache during Linear triage

### WHAT

A default Goldfish `recall()` returned workspace `/home/murphy/.codex/plugins/cache/goldfish/goldfish/7.9.0`; the same call with `workspace: /home/murphy/source/goldfish` returned the repository's actual brief and checkpoints.

### WHY

This is concrete evidence that the installed Codex plugin can treat its own cache as the active project. The current Linear binding watch, BRE-29, is scoped to Cursor and does not cover this Codex reproduction.

### HOW

Verified the mismatch with two live recall calls. Miller inspection showed `hydrateWorkspaceArguments` falls back to cwd and `recoverWorkspace`, while the unsafe-cwd guard rejects only filesystem roots, home directories, and Windows system directories. A plugin cache below home is accepted. Because the cache contains `.memories`, recovery can select it as a project.

### IMPACT

Default recall reads the wrong history, and workspace-aware mutating tools share the same hydration path, so they risk writing checkpoints or briefs into the disposable plugin cache. Triage should create a high-priority Codex binding issue or widen the existing binding work only if the root cause is proven shared.
