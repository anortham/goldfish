## User-level registration plus stateless MCP requires per-call workspace identity

### WHAT

Corrected the workspace-binding recommendation after the user clarified that the target is a user-level MCP registration and Goldfish is adopting MCP 2026-07-28 stateless behavior.

### WHY

A traditional `activate_workspace` tool stores hidden state in a particular server process or protocol session. MCP 2026-07-28 removes the protocol session and `Mcp-Session-Id`; later calls may reach a fresh server instance. User-level registration also cannot set a different `GOLDFISH_WORKSPACE` for each active project.

### HOW

Verified SEP-2567 and the current MCP specification: cross-call state must be represented by an explicit handle returned by one tool and passed back in later tool arguments. Goldfish's completed v2 migration already avoids modern Roots and has `ctx.sessionId` fall back to one `DEFAULT_SESSION_KEY`, confirming that session-keyed workspace activation would be unsafe. A workspace handle would still need to appear on every call and would add lookup, expiry, and collision concerns. Passing the absolute workspace path is the smaller interface.

### IMPACT

For user-level installs, `workspace` should become required at runtime for checkpoint, brief, and current-workspace recall unless the request carries another verified explicit identity. Project-level env configuration remains a valid convenience. Cwd, parent walking, and the registry may produce error suggestions, but must not authorize a workspace. Tests should prove fail-closed behavior under plugin-cache cwd and modern undefined-session calls.
