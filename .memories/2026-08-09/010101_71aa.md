## Task 2 phase complete: dual-era stdio

### WHAT

Task 2 switched `startServer()` to the v2 `serveStdio(() => createServer())` factory, exported the plain-data `hydrateWorkspaceArguments()` seam, and added a `canRequestRoots` guard derived from `ctx.mcpReq.envelope`. Spawned stdio tests now pin the 2026-07-28 modern era and verify tools, workspace precedence, refusal, and cleanup.

### WHY

The v2 package baseline alone still served only the legacy protocol. This phase adds real modern stateless stdio compatibility while preserving legacy clients and keeping modern roots MRTR out of scope.

### HOW

The worker followed red-green TDD: the focused bypass test first failed because the seam was not exported, and the spawned tests failed modern negotiation against direct `StdioServerTransport`. The reviewed implementation uses `ctx.mcpReq.envelope === undefined` only at the adapter boundary, passes a boolean into workspace hydration, and uses `void serveStdio(() => createServer())`. Miller inspection/tracing/impact confirmed the public seam has one production caller and no additional dependents.

### IMPACT

Modern and legacy stdio behavior are both proven. Task 3 can now document the compatibility contract and prepare version 7.7.0 metadata without changing runtime behavior. Release, push, tag, and publish actions remain out of scope.
