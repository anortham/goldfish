## Memory-value transcript audit found the `summary: WHAT` bug

**WHAT:** Audited 208 Goldfish recalls from Claude (since 2026-08-25) and Codex (since 2026-08-12) transcripts across all projects. Five subagents judged each recall. Fixed compact summaries that showed only "WHAT".

**WHY:** TODO.md item 3 (measure memory value) must come before item 1 (cut checkpoint triggers). CLAUDE.md requires evidence before a policy change.

**HOW:**
- Found 1,151 writes and 227 recalls. 70% of written checkpoints never appeared in a recall result.
- 46 of 208 recalls changed what the agent did, 80 only oriented it, 80 went unused, and none misled it. The `next` handoff line drove most "changed" results (24), then decisions (11), status notes (11), and failures (5).
- `generateSummary` took the first line, so a description that starts with `## WHAT` got the summary "WHAT". This hit more than 950 stored files. Added `isSectionLabel` (a heading of one short word, colon optional). Summaries and compact search headings now skip these labels. `parseCheckpointFile` rebuilds a stored label-only summary from the body, so old files are fixed on read without rewriting them. Checked on 967 real files: 966 now get a real summary.
- Did not fix: the Orama English tokenizer splits dotted versions ("3.3.1" becomes "3", "1"), and the all-terms search pass can hide a better any-term match. Both need a ranking design choice.

**IMPACT:** Compact recall is useful again for checkpoints in WHAT/WHY/HOW format. The results are recorded under item 3 in TODO.md. They support keeping handoff and decision triggers, and do not yet support removing status checkpoints. Full suite: 673 pass. Typecheck is clean. Not committed.
