## Version-number search and Orama all-terms bug fixed

**WHAT:** `src/ranking.ts` now indexes dotted versions ("2.41.1", "v2.0.0", "julie-2.41.1") as whole terms, not bare digits. The all-terms search pass now runs one Orama search per query term and intersects the results.

**WHY:** The English splitter turned "3.3.1" into "3" and "1", so a version query matched unrelated releases. Orama's threshold=0 mode counts matched index words, not query terms, and requires an exact count. A term that prefix-matches two words in one field ("auth" in "auth" and "authentication", "juli" in "julie-extract") pushed the count too high, so Orama dropped the documents that matched best.

**HOW:** `createSearchTokenizer` wraps Orama's English tokenizer. `splitVersions` takes out versions (and a hyphen before them), then the default tokenizer handles the rest. `queryTerms` splits the query the same way. The all-terms check now matches across all fields, not inside one field. Tests were written first: a version-search group and a multi-word regression.

**IMPACT:** Exact version queries now return only matching checkpoints, and multi-word searches keep their best matches. The CHANGELOG has an [Unreleased] entry. Not committed.
