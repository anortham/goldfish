## Search gaps closed: compound-word parts, checkpoint IDs, fallback order

**WHAT:** Made three changes in `src/ranking.ts`.
1. Words joined by `-` or `_` now index whole and also as their parts (`compoundParts`). `queryTerms` splits the query the same way, so "julie-extract" still requires both "julie" and "extract".
2. A new `checkpoint` search field holds the checkpoint ID, with boost 5.0, the highest.
3. When no hit matches every query term, hits that match more terms rank first, and BM25 score breaks ties.

**WHY:** The audit found two misses that the version fix did not solve. First, "delegation gate" matched only a hyphenated brief ID (`agent-tier-delegation-gate-policy-feedback`). Second, "JVM source identity mapping c1902f4f" was a query by checkpoint ID.

**HOW:** Tests were written first, and each failed before its fix. A boost of 1.0 for the ID field left the JVM target at rank 7 of 1,114; a boost of 5.0 moved it to rank 1. A test fails at 1.0 and passes at 5.0.

**IMPACT:** Every search miss from the audit now finds its target. Building the index without a cache is about 45% slower: 1.0 s became 1.5 s at 1,950 checkpoints. Most of the extra time is Orama adding the extra part words to the index; tokenizing is about 110 ms of it. Cached queries take the same time (5–19 ms). Full suite: 687 pass. Typecheck is clean. Not committed.
