## Documented markdown-database interop in README

**WHAT:** Added a paragraph to README "Storage Format" noting that `.memories/` is itself a markdown database: plain markdown + YAML frontmatter, so generic tools work on it. Example given: open the project in Obsidian and point a Base at `.memories/` for a sortable, filterable checkpoint table.

**WHY:** Review of https://wayofmarkdown.com/markdown-database (the "Markdown Database Pattern") confirmed Goldfish already implements the pattern — files as records, frontmatter as columns, date dirs as tables, derived index kept in memory. The only gap was that this free interop was undocumented.

**HOW:** Doc-only change; no code. Verified with `bun test agent-assets` (11 pass), which guards usage-doc freshness.

**IMPACT:** Users learn they can browse checkpoints with Obsidian Bases or MarkdownDB with zero Goldfish code. Also recorded decision: **no SQLite index** — all perf targets pass with wide margins, FTS5 vs Orama is BM25 either way, a derived on-disk index can go stale/corrupt and invites multi-process lock contention, and iteration 2 (Tusk, Bun+SQLite) died of exactly that complexity. Revisit only with profiled evidence of recall missing its targets.
