## WHAT
Cross-project recall now returns each shared checkpoint once, reuses its search index, and the registry removes dead entries. Branch `feat/cross-project-dedup-registry-prune`. Files: `src/recall.ts` (`dropSharedCheckpoints`, cache key for whole-corpus cross-project search), `src/ranking.ts` (`idleReleaseMs` on `SearchCacheKey`), `src/registry.ts` (`dropDeadEntries` inside `registerProject`).

## WHY
The owner approved a reversal of the 2026-11-03 F8 decision after new measurements: 60% of checkpoint files across live projects were copies, cross-project search took 15 s per call, and 155 of 195 registry entries pointed to deleted folders.

## HOW
- Match key is id plus timestamp, not id alone: an 8-hex id can collide between unrelated checkpoints.
- The project with the earliest `registered` time keeps a shared checkpoint; path order breaks a tie. The owner gave no label rule, so this is my choice.
- The index cache key applies only when no date window or structured filter is active.
- The cached cross-project index held about 400 MB of heap on real data, so it is dropped after 5 idle minutes.
- Pruning runs only when a new project registers, removes `ENOENT` paths only, and reads never write.

## IMPACT
Real data: search 15.4 s to 6.1 s cold and 0.16-0.18 s warm, no repeated results. Cold search still misses the 500 ms target; the index build over 6,700 unique checkpoints (9 MB of text) is the remaining cost. Not pushed, not merged, no version bump.
