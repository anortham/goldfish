## Periodic project review (7.6.1, ~2 weeks post-release)

Health check-in with no specific focus. Suite green after repair: 619 pass / 0 fail, tsc clean, version-tag check passes, no open issues/PRs.

### Bug found: test suite pollutes the live registry
Running `bun test` wrote 12 `/tmp/test-server-*` entries into the real `~/.goldfish/registry.json` (it even created the file — it didn't exist on this machine before).

- **Root cause:** `server.test.ts` calls checkpoint handlers in-process without setting `GOLDFISH_HOME` in its global setup; `saveCheckpoint` → `registerProject()` resolves to the real home. Only 5 individual tests in that file set `GOLDFISH_HOME`.
- **Contrast:** `registry.test.ts` isolates properly (explicit registryDir); `checkpoints.test.ts` works around it by calling `unregisterProject(tempDir)` in teardown — which still transiently writes the real registry and leaks on crash.
- **Impact:** every dev-machine test run leaves dead /tmp paths that `workspace: "all"` recall/standup then iterates. No data loss (registry writes are additive under lock).
- **Suggested fix:** bunfig preload setting `GOLDFISH_HOME` to a per-run temp dir for the whole suite, plus a guard test. Cleanup done: polluted registry file deleted (auto-heals).

### Other findings
- **No CI.** Today node_modules was locally broken (MCP SDK dir missing) — suite silently ran only 178 of 619 tests. A minimal GitHub Actions workflow (`bun install --frozen-lockfile && bun test && tsc --noEmit`) would catch this class.
- **Deps behind:** MCP SDK 1.26.0 → 1.30.0, yaml 2.8.2 → 2.9.0, @types/bun 1.3.9 → 1.3.14. TypeScript 7.0.2 (native compiler, major) is out; repo pins 5.9.3.
- **Hooks tier not dogfooded here:** goldfish runs via repo `.mcp.json` dev mode; the plugin isn't installed on this machine, so the 7.6 SessionStart hook never fires in dev sessions — even though this session demonstrated exactly the harness behavior it targets (goldfish tools deferred behind ToolSearch).
