## Worktree checkpoints recorded the main checkout's git state

**WHAT:** A code-kb 2.0.2 session passed `workspace=<repo>/.worktrees/julie-3.5.0-code-kb-2.0.2`. The file landed in the worktree, but the reply and frontmatter said `branch: main`, `commit: 1373ba8`, `worktree: /home/murphy/source/code-kb`. It looked like the save went to main.

**WHY:** `resolveGitCaptureCwd` (7.9.0 "G2") ran git in the server's `process.cwd()` when it shared a git common dir with the workspace. The server's cwd is its launch directory and never follows Claude Code `EnterWorktree`, so it picked the main checkout. G2 was designed before fail-closed explicit workspaces (8.0), when cwd was assumed to track the agent.

**HOW (branch `fix/worktree-workspace-binding`, uncommitted):**
- `saveCheckpoint` reads git context and git identity from the workspace path only. Deleted `resolveGitCaptureCwd` and its tests. New saves never write `git.worktree`; old files still parse.
- `hydrateWorkspaceArguments` asks `roots/list` on every call. The per-session roots cache went stale because Claude Code sends no `list_changed` after `EnterWorktree` (proved in the code-kb probe).
- Save reply prints the absolute file path.
- One sentence on every surface (instructions, `workspace` param, hook, 6 skills + mirror): "In a git worktree, pass the worktree path, not the main checkout."
- Fixed a timing race in `tests/recall.test.ts` exposed by faster saves (same-ms timestamps tie with `limit: 1`).

**IMPACT:** Checkpoints in a worktree now record the worktree branch and are visibly placed. Matches the code-kb 2.1.0 decision: never pick a root from server state or process cwd.
